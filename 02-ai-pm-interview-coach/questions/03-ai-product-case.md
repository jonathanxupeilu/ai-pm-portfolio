# 域三：AI 产品设计 Case（20题）

> 大厂面试重头戏，通常给开放式命题限 10-15 分钟。考察结构化拆解、场景洞察、AI 约束下的方案设计。答题骨架：澄清目标→用户与场景→方案设计→指标→风险与边界。切忌上来就堆功能。

### Q3-01｜设计一个 AI 搜索产品，它和传统搜索的本质差异是什么？
- 难度：★★★★ ｜ 考察点：AI搜索、产品架构
- 参考要点：
  - 本质差异：传统搜索给"链接列表"（用户自己找答案），AI 搜索给"直接答案"（信息消费模式从检索变为问答）
  - 架构：查询理解→检索（多路召回）→重排→生成（带引用）→兜底
  - 关键设计点：引用溯源（信任的地基）、确定性（同一问题答案稳定）、时效性（实时信息接入）
  - 指标：回答采纳率、引用点击率、零点击后的满意度（ 反直觉：AI 搜索成功=用户不点链接也满意）
  - 风险：幻觉内容伤害信任一次就够；版权与流量生态反噬
  - 加分项：按搜索意图拆解替代程度——基础信息查询（被大比例替代）、比较决策类（部分替代）、需要履约的服务交易类（AI 只能当入口不能闭环，Agent 化是终局）（100题集补充）
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-02｜设计一个 AI 客服产品，如何衡量它是否成功？
- 难度：★★★ ｜ 考察点：AI客服、指标设计
- 参考要点：
  - 场景分层：FAQ 类（高置信自动答）→ 业务操作类（查订单/退款，接 API 执行）→ 复杂投诉类（转人工，别硬答）
  - 核心指标：问题解决率（一次会话内解决，不是"回复率"）、转人工率、人工接管后的二次解决率（AI 答错让用户白跑的隐性成本）
  - 商业指标：人工坐席成本节约、首响时长下降、CSAT 变化
  - 关键设计：AI 不知道就说不知道并快速转人工——错误自信是客服场景头号杀手
  - 加分项：知识库运营机制——badcase 自动归档进知识库待补，形成闭环

### Q3-03｜给电商业务设计一个 Agent 应用，你会怎么规划？
- 难度：★★★★ ｜ 考察点：Agent设计、业务落地
- 参考要点：
  - 选题原则：先找"多步骤、规则明确、错误可回滚"的任务——如商家上架商品（填参数、写文案、审合规）
  - 方案：Agent 拆解任务（读商品资料→生成标题详情→自检合规→提交人审），工具=内部 API
  - 人机边界：初期限"草稿产出"模式，采纳率稳定后逐步放权到自动提交低风险类目
  - 指标：任务完成率、人工修改幅度（编辑距离）、单任务成本 vs 人工成本
  - 风险：错误累积（第一步错步步错）→ 每步设校验卡点；成本失控 → 步数上限+模型分级
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-04｜设计一个"AI 面试陪练"产品，你会怎么做？
- 难度：★★★ ｜ 考察点：产品设计、元认知
- 参考要点：
  - 用户与场景：求职者考前模拟，核心痛点不是"没人陪练"而是"练完不知道差在哪"
  - 核心循环：出题→作答→结构化点评（亮点/不足/框架/参考）→薄弱点追踪→针对性再练——点评质量即产品壁垒
  - 关键设计：题目与真实招聘市场联动（按 JD 热点更新）、避免"背题"导向（给框架不给答案）
  - 指标：周练习留存、点评采纳后的进步幅度（同题重测分数）、付费转化
  - 风险：点评敷衍=一次性产品；与真面试差异过大=信任崩塌
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-05｜如何为一个成熟产品（如输入法/相册）增加 AI 能力而不破坏原有体验？
- 难度：★★★ ｜ 考察点：AI功能植入、体验设计
- 参考要点：
  - 原则：AI 是"增强项"不是"重构项"——老用户路径零改变，AI 能力渐进露出
  - 场景选择：从"高频+低风险+AI 显著优于旧方案"切入（相册：搜索/修图；输入法：整句润色）
  - 交互设计：AI 结果作为"可选建议"呈现（生成候选，用户一键采纳），永远可撤销
  - 性能约束：成熟产品对时延极敏感——本地小模型+云端大模型混合路由
  - 指标：功能渗透率（多少用户发现并用了）、采纳率、老功能留存无回退
  - 加分项：提醒"AI 按钮综合症"——堆一个 AI 入口≠AI 化，先想清楚哪个环节最痛
- 来源：考点出处：牛客网〈飞书 LLM 产品岗面经〉https://ac.nowcoder.com/discuss/1554426（2025-09-14） · 原题为「给飞书加 AI 助手」，本地改写为通用母题

### Q3-06｜AI 生成内容的产品，如何设计审核机制？
- 难度：★★★ ｜ 考察点：内容安全、合规
- 参考要点：
  - 分层审核：模型层（对齐与安全策略）→ 规则层（敏感词/分类器）→ 人工层（高风险抽检+用户举报响应）
  - 分级策略：按内容风险分级——公开发布>私域存储>草稿自用，风险越高审核越重
  - 实时性设计：生成时前置拦截（prompt 侧防护+输出过滤）+ 事后巡查兜底
  - 合规底线：生成式 AI 管理办法要求——标识 AI 生成内容、留存日志、备案
  - 加分项：审核不是成本是产品——用户举报响应速度决定平台信任；误杀率与漏杀率要平衡并给申诉通道

### Q3-07｜设计一个企业知识库问答产品（RAG），关键设计点有哪些？
- 难度：★★★ ｜ 考察点：RAG产品、企业场景
- 参考要点：
  - 数据侧是成败关键：文档权限继承（谁能看什么就检索什么）、文档质量治理（过期文档比没有更糟）、更新同步机制
  - 检索设计：混合检索（语义+关键词）、按部门/文档类型过滤、引用到原文段落（可点击溯源）
  - 兜底：检索不到就明说"知识库暂无"，禁止模型自由发挥——企业场景幻觉的代价是信任+法律风险
  - 指标：回答准确率（抽检评估）、引用命中率、周活跃提问人数、未被回答问题清单（知识库缺口信号）
  - 加分项：冷启动策略——先接最高频的部门（如HR/IT答疑），快速出效果再扩

### Q3-08｜AI 推荐与经典推荐算法在产品上的差异？怎么设计？
- 难度：★★★★ ｜ 考察点：推荐系统、LLM+推荐
- 参考要点：
  - 经典推荐：协同过滤/深度模型，毫秒级、海量候选、可解释性弱；强项是规模与实时性
  - LLM 推荐：能理解内容语义与用户长尾意图（"想看类似上周那部冷门纪录片"）、可对话式交互调整、冷启动强（靠语义理解不靠行为积累）
  - 差异落地：LLM 适合候选量小+语义重的场景（内容精选/导购对话），不适合全量毫秒级排序
  - 混合架构：经典召回（效率）+ LLM 重排/解释（质量与可解释性）是当前务实解
  - 指标差异：除 CTR 外看"推荐对话完成率"、用户主动纠偏后的调整响应度
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-09｜设计数字人/语音助手产品，核心体验挑战是什么？
- 难度：★★★ ｜ 考察点：语音交互、多模态体验
- 参考要点：
  - 三层体验链路：听清（ASR 准确率，方言/噪音场景）→ 听懂（意图理解）→ 像人（TTS 自然度+情感+延迟）
  - 核心挑战一：时延——对话超过 1.5 秒停顿就有"掉线感"，全链路时延预算要拆解到每个模块
  - 核心挑战二：打断与多轮——人说话会改口、插话，系统要支持自然打断（barge-in）
  - 拟人度的产品权衡：越像人期待越高，说错话的信任惩罚越重——恐怖谷在交互层同样存在
  - 指标：任务完成率、对话轮次效率（几轮解决）、打断后恢复成功率
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-10｜用户不会用/不敢用 AI 功能，用户教育怎么做？
- 难度：★★★ ｜ 考察点：用户教育、信任建设
- 参考要点：
  - 先诊断是哪种："不会用"是能力问题（不知道能干嘛），"不敢用"是信任问题（怕错/怕泄密/怕担责），药方不同
  - 不会用→降低表达门槛：示例 prompt 引导、模板化输入、把复杂能力拆成具体场景按钮（"帮我改写得更正式"而非一个空输入框）
  - 不敢用→建立信任：展示引用来源、先在低风险场景证明能力（草稿建议）、数据安全承诺前置、允许随时撤销
  - 机制设计：首次体验做减法——一个场景打透胜过功能大全；把"成功的第一分钟"当核心设计对象
  - 加分项：内部场景补一条——找种子用户当"布道者"，同伴示范比官方教程有效
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-11｜面向企业的 AI 产品和 toC 的核心差异是什么？
- 难度：★★★★ ｜ 考察点：toB、toC差异
- 参考要点：
  - 决策链差异：toC 用户=购买者，toB 用户≠购买者（老板买单、员工使用、IT 部署）——产品要同时服务三种角色
  - 价值验证：toC 看体验直觉，toB 看 ROI 证明（省了几个人天/几万成本），销售周期长但留存高
  - 交付形态：私有化/专有云、SSO 权限集成、审计日志是标配需求；"能跑通 demo"和"能过安全评审"是两回事
  - 数据敏感：客户数据不出域是常见红线，模型选型受合规约束
  - 加分项：toB 的护城河是工作流嵌入深度——嵌进客户日报流程的功能，替换成本极高
- 来源：模型生成·无外部出处（2026-09-07）

### Q3-12｜AI 新功能上线，灰度发布策略怎么设计？
- 难度：★★★ ｜ 考察点：灰度发布、风险管理
- 参考要点：
  - 阶梯设计：内部 dogfood → 1% 流量 → 10% → 50% → 全量，每档设观察期与晋升/回退标准
  - 灰度维度不止流量：按用户群（新用户先行）、按场景（低风险类目先行）、按地域
  - AI 特有：同一灰度档内做 A/B（新旧模型对照）；准备"一键回退到旧模型/旧 prompt"开关——模型层要有版本化
  - 观察指标分层：质量指标（badcase 率）领先看、行为指标（留存）滞后看、成本与安全指标全程盯
  - 加分项：小流量期主动收集 badcase 修评测集，全量前把已知问题清零
- 来源：JD能力要求出处：美团招聘〈搜索产品经理·AI方向〉https://zhaopin.meituan.com/web/position/detail?jobUnionId=4549616172（已验证可访问） · 该 JD 明确要求「A/B 实验与灰度」，题干为本地扩展

### Q3-13｜（母题）请设计一个 AI 产品，解决 XX 领域的痛点
- 难度：★★★★ ｜ 考察点：产品设计流程、结构化思考
- 参考要点：
  - 设计题万能流程：发现痛点 → AI 方案（为什么 AI 比传统方案优）→ 核心功能与交互流程 → 商业模式
  - 痛点分析：挖到深层需求（"更快的马"背后是"更快到达"），不停留表面
  - AI 方案论证：说清"AI 在哪一环产生不可替代的增益"（理解/生成/预测），讲不出增益点的方案是伪 AI 需求
  - 功能落地：给具体例子与交互细节（如 AI 健身教练用视觉识别动作、给实时反馈），忌空泛谈概念
  - 收尾必备：指标（怎么算成功）+ 风险（幻觉/成本/合规）——大厂面试官等的就是这两步

### Q3-14｜用大模型做一个"高度拟人化的情感陪伴机器人"，技术方案怎么设计？有哪些风险？
- 难度：★★★★ ｜ 考察点：方案设计、伦理风险
- 参考要点：
  - 方案骨架：人设与记忆（长期记忆库存偏好/事件/关系线，多级记忆架构）→ 多模态交互（语音语调+情感识别）→ 状态跟踪（情绪识别→共情回应策略→危机信号升级人工）
  - 拟人化的工程实现：角色一致性（固定人设 prompt+记忆回注）、主动性（基于时间线/用户状态主动关怀，而非被动问答）
  - 风险清单分层：伦理风险（情感依赖/孤独感加剧/未成年人保护）、隐私风险（倾诉内容高度敏感）、安全风险（自伤等危机信号必须识别+干预+转介）
  - 商业与合规：付费墙设计防"情感勒索式变现"；深度合成与 AI 生成内容标识合规
  - 加分项：主动提"拟人度权衡"——越像人期待越高，说错话的信任惩罚越重；保留"AI 身份透明"设计恰恰是长期信任
- 来源：用户提供（2026-09-07）· 人人都是产品经理〈2万字拆解100道AI产品经理面试题〉

### Q3-15｜设计面向 C 端的 AI 法律咨询产品，如何平衡大模型能力与局限？
- 难度：★★★★ ｜ 考察点：高风险场景设计、人机边界
- 参考要点：
  - 场景分层先行：法律科普/流程指引（AI 可答）→ 文书起草（AI 草稿+免责）→ 具体纠纷判断（AI 给分析框架+转执业律师）——幻觉零容忍领域必须分层
  - RAG 是生命线：法条/案例库定期更新+权威来源分段引用，每个回答附条文出处可溯源
  - 兜底设计：免责声明前置（"仅供参考不构成法律意见"）、高危信号词（诉讼时效/刑事）触发转人工、禁止给出确定性结论
  - 商业闭环：免费科普引流 → 付费深度咨询 → 律师对接抽成——AI 在中间层提效而非替代
  - 加分项：指出赛道特殊性——错误代价极高+监管敏感，"AI 能力边界设计"本身就是产品竞争力
- 来源：用户提供（2026-09-07）· 人人都是产品经理〈2万字拆解100道AI产品经理面试题〉

### Q3-16｜设计一个用 AI 提效员工报销审批的应用（卡点：发票与行程的闭环验证）
- 难度：★★★★ ｜ 考察点：B端流程设计、多模态落地
- 参考要点：
  - 先拆全流程两端：员工端（发票拍照识别→自动填单→政策预检）+ 审批端（规则预审→异常标记→AI 辅助审批意见）
  - 核心难点"闭环验证"：发票信息 vs 行程/事由 vs 公司政策三方交叉核验——OCR/多模态负责识别与理解，规则引擎负责硬校验，AI 负责解释
  - AI 价值点：自动预审把"人找错"变"错找人"（贴错类目/超标/重复报销识别），异常项给员工即时反馈而非打回重填
  - 指标：报销周期缩短、财务抽检异常率、员工补交次数下降
  - 加分项：点出 B 端落地关键——AI 预审意见只是"建议"，终审权留人；先从高争议场景（如超标豁免解释）证明价值再全流程铺开
- 来源：用户提供（2026-09-07）· 人人都是产品经理〈2万字拆解100道AI产品经理面试题〉

### Q3-17｜（现场实操）做一个"简历关键信息提取与查询"应用：上传多份 PDF → 提取姓名/自我评价/工作与教育经历成表格 → 支持自然语言查询（如"列出南大毕业的"）
- 难度：★★★ ｜ 考察点：现场实操、输入-逻辑-输出映射
- 参考要点：
  - 先澄清再动手：文件规模（几十份还是几万份）、字段口径（工作经历怎么算一段）、查询范围——现场题先问后做是大厂基本功
  - 方案骨架：PDF 解析（文本层抽取）→ LLM 结构化提取（每份输出固定 JSON schema）→ 入表存储 → 查询层（自然语言→结构化过滤，走字段映射或 Text2SQL）
  - 设计要点：批量处理与失败重试（解析失败的文件要报告而非静默丢）、编号与原文件一一对应（可溯源回原文）
  - 用低代码（如扣子/Agent 工作流）快速搭 demo 也行，关键是讲清"输入→逻辑→输出"的映射链
  - 加分项：主动提边界——扫描版 PDF 需要 OCR、复杂查询会暴露 Text2SQL 局限，给出升级路径
- 来源：用户提供（2026-09-07）· 人人都是产品经理〈2万字拆解100道AI产品经理面试题〉

### Q3-18｜让 AI 根据模糊需求（如"帮我策划线上活动"）输出完整方案，多步骤任务怎么设计？
- 难度：★★★ ｜ 考察点：意图澄清、多步工作流
- 参考要点：
  - 核心思路：模糊需求的解法不是"模型更聪明"而是"流程补全"——把一次性生成改为"澄清→草稿→迭代"多步交互
  - 步骤一意图澄清：用 5W1H 模块化追问（目标人群/预算/时间/成功标准），一次问全但分组呈现，别让用户答 20 个问题
  - 步骤二方案生成：意图识别结果映射到方案模板骨架，AI 按模块填充（主题/玩法/传播/预算/风险预案）
  - 步骤三反馈迭代：让用户按模块点选修改而非整体重来；每轮确认后锁定，防止改 A 动 B
  - 加分项：产品化意识——把这套流程做成"引导式输入界面"（结构化表单+AI 补全），比纯聊天框体验好一个量级
- 来源：用户提供（2026-09-07）· 人人都是产品经理〈2万字拆解100道AI产品经理面试题〉

### Q3-19｜多智能体（Multi-Agent）相比单 Agent 的优势与风险？设计一个多 Agent 协作场景
- 难度：★★★★ ｜ 考察点：多智能体编排、任务分解、错误累积
- 参考要点：
  - 优势：任务并行提速、角色专业化（planner/executor/critic 分工）、单点失败可隔离
  - 风险：错误在 agent 间累积放大、成本随 agent 数线性甚至超线性增长、协调开销、调试难度陡增
  - 设计要点：先答"为什么要拆"——单 agent 上下文不够 / 任务可并行 / 需要专业分工才值得拆，否则是过度设计
  - 必答：human-in-the-loop 放哪一环、agent 间通信协议、失败如何回滚
  - 加分项：2026 年 MCP 成事实标准后"接工具"成本下降，多 agent 的瓶颈从工具接入转向编排与治理
- 来源：真题出处：CSDN MCP 技术社区〈多智能体从概念验证走向核心运营〉https://mcp.csdn.net/6a75caea662f9a54cb99790e.html（2026-08-07）

### Q3-20｜AI 编程工具已分化为编排层/执行层/审查层三栈，这对 PM 设计该类产品有何启示？
- 难度：★★★★ ｜ 考察点：AI Coding 产品分层、价值定位
- 参考要点：
  - 三层划分：编排层（Cursor 类，管理人机协作与上下文）、执行层（Claude Code/Codex 类，自主跑长程任务）、审查层（diff 审查与测试验证）
  - 启示一：PM 必须明确产品站在哪一层——三层的用户心智、核心指标、护城河完全不同
  - 启示二：执行层看"任务完成率"，编排层看"人机分工是否顺手"，别用同一套指标衡量
  - 启示三：审查层被低估——模型越强生成量越大，人工审查成为新瓶颈，这是产品机会
- 来源：真题出处：The New Stack〈AI 编程的三层工作划分〉https://thenewstack.io/?p=22817152（2026，已验证可访问）
