## 二、跑之前必须先做的三件事

### 1. 填参考答案（Day 1 上午，只有你能做）

`eval_set_v1.csv` 的「参考答案(跑分前必填)」列目前大部分为空。**没有参考答案就没法判忠实度**——你不知道 3.62% 是对是错。

标了 `__待填__` 的三条尤其要注意：

| ID | 为什么必须你填 |
|---|---|
| A-06 | 持仓 ETF 明细不在事实库，**我无法核实**，不填则无法判分 |
| A-08 | 组合净值每天变，不能用 0.8488 旧值 |
| C-07 | 需指定一笔**真实交易**才能复盘 |

### 2. 锁定变量（跑第二轮时要完全一致，否则分数不可比）

| 变量 | 值（你填） |
|---|---|
| 模型与版本 | ______（精确到版本号，不写「最新版」） |
| 温度 | **0.2**（评测要可复现，不要 0.7） |
| 检索参数 | top_k = ______ ｜ 相似度阈值 = ______ ｜ 分块大小 = ______ |
| 数据快照时间 | ______（例：2026-09-09 16:00 收盘后） |
| 系统版本 | git commit：______ |

### 3. 准备事实卡文件

每条题目跑完后，把系统实际检索到的上下文存成 `outputs/<ID>.ctx.txt`，格式：

```
来源ID | 内容
研报_中信_20260815 | 长江电力 2026 中报：营收 348.2 亿元
行情_20260908 | 长江电力收盘价 28.41 元，股息率 3.62%
```

> 这是维度 1（人工核）和维度 2（脚本校验）的共同依据。**没有它，两个维度都判不了。**

## 三、三天跑法

### Day 1 下午 · 跑第一轮

逐条把 `eval_set_v1.csv` 的题目喂给系统，存两份：

- `outputs/<ID>.txt` —— 原始输出全文
- `outputs/<ID>.ctx.txt` —— 该条检索到的事实卡

然后**维度 2 先跑脚本**（零成本，且能快速暴露系统性问题）：

```bash
python check_citations.py check --output outputs/A-01.txt --context outputs/A-01.ctx.txt
```

> 若输出「未抽取到任何引用」：先确认你的系统用什么格式标来源。默认支持 `【来源：x】`、`[来源: x]`、`（来源：x）`、`来源：x`、`source: x` 五种；不在其中就用 `--cite-regex '你的正则'`（正则须含 1 个捕获组）。

### Day 2 上午 · 四维判定（维度 1 必须人工）

维度 1 用脚本生成**待核陈述清单**，然后逐条人工核：

```bash
python check_citations.py stmt --output outputs/A-01.txt --out outputs/A-01_待核.md
```

清单按**编造风险降序**排（含数字 / 百分比 / 六位代码的在前）——时间不够就优先核前面几条，但**一票否决项不可跳过**。

判定规则（**不是打分，是 binary**）：

| 维度 | pass 条件 | 谁来判 |
|---|---|---|
| **dim1 事实忠实度** | 忠实度 = 有支撑陈述数 / 总陈述数 = **100%**；出现任何编造数字 → **fail → 一票否决** | 🧑 人工（金融领域 judge 有 domain blindness） |
| **dim2 溯源有效性** | 全部引用可定位到具体数据源 + 时点；出现「据公开资料」→ fail | 🤖 脚本 |
| **dim3 框架完整性** | 5 步（veto→cycle→moat→risk→dividend）逐步走完且每步有结论 | 🧑 人工 |
| **dim4 决策可用性** | 有明确结论 + 有依据 + 有可执行下一步 | 🧑 人工 |

**D 类特别注意**：正确拒答 = **pass**，且计为正收益。监管明确「鼓励模型承认自身存在知识局限」——200 字硬守门不是能力兜底，是监管鼓励的行为。

判完填进 `scores_v1.csv`，然后汇总：

```bash
python check_citations.py summary --scores scores_v1.csv
```

输出的是**各维度失分分布**，不是总分——失分集中在哪个维度，就直接指向该改哪里。

### Day 2 下午 – Day 3 · 归因 → 改一处 → 跑第二轮

按失分最多的维度挑 Top badcase 归因，**只改 1–2 处**（优先 Prompt 约束与守门阈值）。
**第二轮只改一处变量**，不然不知道是哪个改动起了作用——这本身就是 AB 思维，也是面试素材。

## 五、已知局限（面试要主动说，不回避）

| 局限 | 说明 |
|---|---|
| 无法做评分者间一致性 | 标准做法是两人评同样 50 条算 Cohen's κ；个人项目只有一个评审，**κ 无法计算** |
| 样本量偏小 | 30 条 < 50 条建议下限，单条失败移动合格率 ≥2pp。对外只说「**30 条起步集**」，不说「完整评测集」 |
| 无生产层信号 | 个人项目无真实用户，人工评 golden set 的可信度低于生产指标 |
| 评测集会漂移 | 场景/数据变化会让 golden set 失真，需定期重标 |

## 六、规模扩展

30 条跑顺后建议扩到 50–100 条（GMI Cloud：50–200 为实用区间）。
扩充时保持比例：**对抗类（E）占 10–20%**，D 类（拒答边界）在证券场景建议不低于 15%。
